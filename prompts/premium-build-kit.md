## Preferred Stack

- React
- Vite
- TypeScript
- Tailwind CSS
- shadcn/ui composition patterns
- Radix UI primitives for accessible interactive elements
- Framer Motion for tasteful motion
- Lucide React icons
- class-variance-authority for component variants
- clsx and tailwind-merge for class composition
- React Hook Form and Zod for forms
- Zustand only when local UI state needs a small store

## Visual Bar

The generated site must feel custom, vivid, premium, and modern. Avoid the default navy bubble look, plain centered hero, generic three-card grid, raw HTML styling, and template sameness.

Every client-ready site must use the local design runtime and declare the premium renderer. Fallback, simple, static_basic, and emergency renderers are dev-only and block publish.

Every client-ready site must also create a media generation plan. If no real/generated media is attached, create the local SVG poster fallback and show the provider-ready Veo/Runway/OpenAI/Imagen prompts as blocked until confirmed.

## Source Visual Keys

Before generating or finishing a site, select source visual keys from `lib/design-runtime/source-visual-keys.ts`.

Use them as inspiration for local components only:

- AdClimber keys: glass cards, gradient mesh, floating orbs, holographic headline motion, media-kit format rails, credit guard panels.
- Putting Green Designer candidate keys: turf contours, precision planning board, angled surface hero, estimator widgets, material chips.
- Rocket mission prototype keys: aurora field, perspective grid floor, fresh-build preview rail, deterministic SVG mockups.

Never copy private component code or brand-specific copy. Recreate the visual behavior inside the Rocket design runtime.

## Publish Safety

Never publish if the QA residue gate finds old company names, old domains, old phones, stale cities, stale schema identifiers, stale social links, placeholder text, or fake claims.
## Strict style/audit include

Include `prompts/style-rules.md` in every Basic, Premier, Domination, Remix, and Finish Pass prompt. The premium build kit is only client-ready when the generated site composes the local premium component kit, uses hero motion, avoids fallback renderer paths, and passes Humanity Audit.
